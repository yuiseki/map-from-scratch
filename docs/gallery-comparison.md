# ギャラリー例の比較計測条件

`TODO.md` の MapLibre GL JS・Leaflet・deck.gl・D3 の各項目で、専用描画器と元例または適切な比較用実装を測るときの条件です。この文書は比較の手順を定めます。既存の測定値が元例より速いことを意味しません。

## 比較対象を揃える

1. 元例の利用者が見える目的と操作を `REQUEST.md` に記録する。元例の固定版 URL またはコミット、データの版・件数・座標系・重み、帰属、配信条件を残す。
2. 同じデータ点と同じ集計規則を使う。転送形式の圧縮や量子化は許すが、表示点数を減らした場合は別条件として扱う。集計値または画面のピクセルを照合する。
3. 初期の中心・ズーム・方位・傾斜、画面サイズ、DPR、表示レイヤー、色・半径などの設定を揃える。背景地図の有無が異なるときは「データレイヤー単体」と「背景込み」を分ける。片方だけ背景を省いた値を総合速度の比較に使わない。
4. 同じ操作経路を使う。パン・ズーム・回転・スライダー操作の各フレームのカメラ値を固定して、両側で再生する。操作が元例で再生できないときは、経路の一致が確認できた項目だけを比較する。

## 実行条件

- 標準画面は `1280×800`、DPR 1、デスクトップ、CPU スロットル 1。モバイルなど別の要件がある例は、その `spec.yaml` の値を両側に適用する。
- 同じマシン、GPU、ブラウザの版で交互に3回以上実行する。結果には日時、CPU、GPU、ブラウザの版、反復数を記録する。GPU がソフトウェア描画ならハードウェア GPU の結果と混ぜない。
- ハーネスは各ナビゲーションでブラウザキャッシュを無効にし、GPU プロセスを予熱する。まずこの条件で初回表示と転送量を測る。暖かいキャッシュの操作が重要な例は、同じ条件の別測定を加える。
- ネットワーク制限を使う場合は、レイテンシと帯域を両側で同じにする。外部ホストの応答が揺れるときはデータを同じローカルサーバーから配信し、その変更を記録する。

## 指標と判定

| 指標 | 測る範囲 |
| --- | --- |
| 初回表示 | ページ開始から必要なデータと初回描画が終わり、画面ピクセルを読み戻すまで |
| フレーム p50/p95 | 固定した操作経路で、描画命令の発行から GPU 完了を待つ読み戻しまで |
| CPU/GPU | JS の描画命令発行時間と、利用可能な場合の GPU タイマークエリ |
| 通信 | キャッシュ無効のページ開始から操作終了までのリクエスト数と転送バイト |
| メモリ | JS ヒープとブラウザのプロセスツリー RSS。同じ計測範囲で比較する |
| 配布サイズ | 利用者が取得するコードとデータの gzip サイズを分けて記録する |

`frame_ms` のような値は測定方法が同じ場合に限って直接比較する。元例の GPU コンテキストや描画完了を同じ方法で観測できない場合は、比較不能な指標として残す。予算達成と元例より速いことは別の判定とする。

各例の `REQUEST.md` に「比較対象」「揃えた条件」「測定結果」「揃えられない条件」を記録する。比較未実施、データ配信の制限、API 鍵、操作経路の再生不可などは、理由と影響を明記する。実測と画面照合が揃うまで「最速」と書かない。
