# deck.gl ScreenGridLayer に対応する専用描画器

## 依頼

> ニューヨークの Uber 乗車地点10万個を画面上の正方格子で集計し、地図を動かしてもセルの件数と色を更新したい。セル幅を変えて密度を見比べたい。PCブラウザで滑らかに動かしたい。

[元例](https://deck.gl/examples/screen-grid-layer) と同じ [10万件の重み付き点](https://github.com/visgl/deck.gl-data/tree/master/examples/screen-grid)を使う。元データは FiveThirtyEight が NYC TLC へ情報公開請求して得た2014年の Uber 乗車地点である。

## 設計

- ベイク時に緯度経度を Web Mercator に変換し、各点を `x:u16, y:u16, weight:u16` の6バイトにする。
- WebGL2 の R32F ターゲットへ、各点の重みを加算ブレンドする。セル幅を変えたときとカメラ移動時に再集計する。
- 格子の最大値は GPU 上で縮約し、セルの色付けまで GPU 上で行う。描画器は deck.gl、React、MapLibre に依存しない。
- 描画結果のピクセルを読み戻して、空の画面でないことを確かめる。
- 背景タイルは読まず、格子そのものを最速で探索する用途に絞る。地名ラベルと個々の乗車地点の選択も付けない。

## 計測

`bin/mfs bench deckgl-018-screen-grid-layer` を3回反復した。GPUは NVIDIA GeForce RTX 3060（Vulkan）。

| 指標 | 結果 | 予算 |
| --- | ---: | ---: |
| 初回描画 p50 | 62.13 ms | 1000 ms 以下 |
| パン・ズーム中のフレーム p95 | 1.40 ms | 8.3 ms 以下 |
| パン・ズーム中の GPU p95 | 0.331 ms | 参考値 |
| 全点表示フレーム p95 | 0.595 ms | 8.3 ms 以下 |
| コード gzip | 4,940 B | 10,000 B 以下 |
| データ gzip | 344,200 B | 500,000 B 以下 |

10万点の重みの合計315,055、画面の色、セル幅による画面変化の3チェックが、各反復で通った。公開用ビルドに対する1回の計測も全予算・全チェックが通り、初回描画212.5 ms、フレーム p95 1.24 msだった。元の deck.gl 版との同条件比較はまだ行っていないため、速度の優劣は主張しない。

別の3回反復では、初回描画 p50 が70.15 ms、パン・ズームのフレーム p95 が1.405 ms、全点表示のフレーム p95 が0.62 msだった。
