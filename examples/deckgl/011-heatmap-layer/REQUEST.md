# deck.gl HeatmapLayer に対応する専用描画器

## 依頼

> ニューヨークの Uber 乗車地点10万個を重みに応じたヒートマップで見たい。地図のパン・ズーム中も更新し、半径・強度・しきい値を操作したい。

[元例](https://deck.gl/examples/heatmap-layer) と同じ [10万件の重み付き点](https://github.com/visgl/deck.gl-data/tree/master/examples/screen-grid)を使う。元データは FiveThirtyEight が NYC TLC へ情報公開請求して得た2014年の Uber 乗車地点である。

## 設計

- ベイク時に緯度経度を Web Mercator に変換し、各点を `x:u16, y:u16, weight:u16` の6バイトにする。
- WebGL2 の画面3分の1解像度の R32F ターゲットへ Gaussian splat を加算ブレンドし、最大密度を GPU 上で縮約する。全画面の色付けは密度を補間して行う。
- 半径・強度・しきい値の操作を独立に受け付ける。背景タイルは読まず、密度面の探索に絞る。
- 元の deck.gl 版との同条件比較は今後実施する。比較が完了するまで速度の優劣を主張しない。

## 計測

`bin/mfs bench deckgl-011-heatmap-layer --site` を3回反復した。GPUは NVIDIA GeForce RTX 3060（Vulkan）、画面は1280×800・DPR 1。

| 指標 | 結果 | 予算 |
| --- | ---: | ---: |
| 初回描画 p50 | 65.94 ms | 1000 ms 以下 |
| パン・ズーム中のフレーム p95 | 3.99 ms | 8.3 ms 以下 |
| パン・ズーム中の GPU p95 | 3.658 ms | 参考値 |
| 全点表示フレーム p95 | 3.985 ms | 8.3 ms 以下 |
| コード gzip | 5,379 B | 12,000 B 以下 |
| データ gzip | 344,200 B | 500,000 B 以下 |

画面の色と高密度域、半径・強度・しきい値による変化の4チェックは各反復で通った。元の deck.gl 版との同条件比較はまだ行っていないため、速度の優劣は主張しない。2分の1解像度ではフレーム p95 が7.10 ms、3分の1解像度では3.99 msだった。両方のスクリーンショットを確認し、表示上の大きな差は見られなかった。
