# deck.gl TripsLayer に対応する専用描画器

## 依頼

> マンハッタンのイエローキャブとグリーンキャブの移動を、建物の間を通る軌跡として時間とともに再生したい。軌跡の長さを変え、地図を動かして比較したい。

[元例](https://deck.gl/examples/trips-layer) と同じ [タクシー経路と建物データ](https://github.com/visgl/deck.gl-data/tree/master/examples/trips) を使う。タクシーの元データは NYC Taxi and Limousine Commission、建物は OpenStreetMap から Mapzen 経由で取得されたもの。

## 設計

- 経路の地点を一度だけ保存し、GPUで隣り合う地点を時刻付きセグメントとして描く。データ内に NYC 外の経路が1件あるため、経路は全世界24ビットのWeb Mercator座標で保持する。建物はマンハッタンの範囲内で16ビットに量子化する。
- 建物をベイク時に屋根と壁のインデックス付き三角形へ変換し、インデックス差分を可変長整数で保存する。経路・建物頂点・建物インデックスをGPUへ各1回転送し、再生中は時刻の uniform だけを変える。
- 時刻と軌跡の長さを操作でき、再生は画面が見えているときだけ行う。
- 元例には背景タイルがあるが、この例にはない。元例との総合速度の比較は背景条件を揃えてから行う。

## 計測

`bin/mfs bench deckgl-025-trips-layer --site` を3回反復した。GPUは NVIDIA GeForce RTX 3060（Vulkan）、画面は1280×800・DPR 1。

| 指標 | 結果 | 予算 |
| --- | ---: | ---: |
| 初回描画 p50 | 96.13 ms | 1000 ms 以下 |
| 再生・カメラ操作中のフレーム p95 | 1.31 ms | 8.3 ms 以下 |
| 再生・カメラ操作中の GPU p95 | 0.116 ms | 参考値 |
| 固定画角フレーム p95 | 0.37 ms | 8.3 ms 以下 |
| コード gzip | 6,416 B | 14,000 B 以下 |
| データ gzip | 458,150 B | 800,000 B 以下 |

建物と両色の経路の表示、時刻・軌跡長による画面変化、再生中のGPUバッファ再転送がないことを確認した。元の2つの JSON は gzip 合計498,293 B、描画用データは458,150 Bだった。最初の方式はセグメントの両端を重複保存して667 KB gzipになり、地点を一度だけ保存する方式に変えると458 KBになった。建物は単純なインデックス化だけでは gzip が大きくなったため、差分符号化した。

元の建物999棟のうち3棟は同じ座標の繰り返しで面積がなく、三角形を作れないため表示しない。残り996棟を描画する。元の deck.gl 版との同条件比較はまだ行っていないため、速度の優劣は主張しない。
