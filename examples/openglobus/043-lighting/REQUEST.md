# OpenGlobus「Lighting Control」の再実装

元例（https://sandbox.openglobus.org/examples/lighting/lighting.html）は、地形とタイル画像を載せた openglobus の地球に
`control.Lighting`（ambient・diffuse・specular の RGB、shininess、Nightlight、gamma・exposure など）と
`control.TimelineControl`（時刻と再生）を付けたものです。この版はその目的、つまり「実際の太陽に照らされた地球の
ライティングをスライダーで調べる」ことだけを WebGL2 で作り直しました。実行時の依存はありません。

## 何をどう描くか

- 球面メッシュ1つ（128×256 格子）を2回描きます。1回目は地球、2回目は半径 1.025 の大気の殻です。
- 地球のフラグメントシェーダー（`shading.ts` の `GLOBE_FRAGMENT`）は openglobus の `getPhongLighting`
  （`src/shaders/common/lighting.glsl`）と同じ形です。
  - 昼: `albedo × (ambient + diffuse × wrap(N·L))`。wrap は N·L に 0.06 を足して 1.06 で割るもので、昼夜境界が
    約 3.4 度ぶん柔らかくなります。
  - 鏡面: `specular × pow(max(R·V, 0), shininess) × 水域マスク`。水域は Natural Earth 10m の海と湖です。
  - 夜: 街明かりのテクスチャを N·L が -0.08〜0.02（太陽高度 -4.6〜1.1 度）の間でフェードインします。昼側には出ません。
  - 最後に exposure を掛け、1/gamma 乗します（openglobus のトーンマッピング選択と whitepoint は省きました）。
- 大気は、殻の各画素について視線が地球中心に最も近づく距離 b を求め、b > 1 なら殻の厚さに向かって薄れる縁、
  b < 1 なら縁に近いほど濃いもやにします。色の強さは最接近点での太陽の向きで決まるので、夜側の縁は暗くなります。
- シェーダーに入る定数（境界の幅、フェード範囲、明かりの色、大気の厚さ）は `shading.ts` から書き出していて、
  テストは同じ値を読みます。
- 太陽の向き（`sun.ts`）は NOAA の太陽位置の簡略式（Meeus 25 章）で赤緯と均時差を求め、太陽直下点の経緯度を
  `経度 = -(UTC 分 - 720 + 均時差) / 4` で出します。2026 年の夏至（赤緯 23.436 度）、冬至、春分、11 月 3 日の均時差
  +16.4 分と照合しています。
- 時刻スライダーは UTC の 1 日の分、日付入力で日を変えます。再生は 1 秒で 2 時間進み、1 日を 12 秒で回します。
- スライダーと時刻の変更は rAF を1つだけ予約して描き直します（再生中だけ毎フレーム描きます）。
- ドラッグは画面中央の地点がポインタについて動くように回し（中央で 1 px = (d-1)/(2.2 × 高さ/2) rad）、
  ホイールは地表からの高さを指数的に変えます。

## データ

| ファイル | 中身 | 出典・ライセンス |
| --- | --- | --- |
| `earth.jpg` 512,606 B | 昼の地球 2048×1024（threejs-006 と同じファイル、sha256 を bake で確認） | Solar System Scope, CC BY 4.0 |
| `water.png` 29,808 B | 海と湖 = 255 のマスク 2048×1024 | Natural Earth 10m land / lakes, public domain |
| `lights.png` 329,806 B | 人口地点から作った発光 2048×1024 | GeoNames 2026-10-01, CC BY 4.0 |

`lights.png` は衛星の夜間光ではありません。GeoNames の feature_class P で人口のある地点 472,711 件
（PPLX と歴史的・廃村を除く、人口合計 44.1 億人）を、人口^0.6 の重みと人口で広がる幅（σ 6〜42 km、
高緯度では経線方向に 1/cos(緯度) 伸ばす）のガウス関数で加算し、1-exp(-x) で圧縮した「人の住む所を光として描いた絵」です。
画面の出典表示にもそう書いています。

## 検証

- 単体テスト（ブラウザなし）: `sun.test.ts`（6件）、`camera.test.ts`（10件）、`shading.test.ts`（7件）、
  `timeline.test.ts`（5件）、`splat.test.ts`（7件）。各テストはモジュールをわざと壊して落ちることを確かめました
  （均時差を外す、赤緯に平均黄経を使う、ドラッグの符号を反転、ドラッグ量を定数に、表裏判定から p を外す、
  夜のフェードをシェーダーに直書き、反射点の反復を 0 回に、スライダー名の変更、再生ステップの上限を外す、
  日付の切り捨てを外す、cos(緯度) の伸びを外す、経度の折り返しを外す、平方根の符号化を線形に、σ を人口によらず一定に）。
- `bench.ts` の実画面チェック: globe-visible、subsolar-brightest、night-city-glows、city-dark-by-day、
  specular-at-reflection-point、sliders-change-pixels、time-moves-terminator、atmosphere-rim、drag-follows-pointer、
  wheel-zooms。
- `bin/mfs bench` はまだ実行していません（計測は別の回で行います）。開発中に `?bench` のページを手元の headless
  Chromium（RTX 3060）で開き、check がすべて通ることと、わざと壊したときに落ちることを確かめました。

## 分かったこと・失敗したこと

- 「太陽直下点が最も明るい」を画素の照度の最大で判定すると外れました。最初はグリーンランドの氷と海の境（59.9 度ずれ）、
  一様な所に絞っても 13.4 度ずれました。頂点付近は照度がほぼ平らで、画像のノイズが勝つためです。
  照度 = c + n·v を最小二乗で当てはめて v の向きを見ると 1.37 度でした。光を視点に付けて回す誤りを入れると 31.2 度ずれて落ちます。
  この check では太陽直下点をわざと画面中央から外しています。中央に置くと、その誤りでも通ってしまうからです。
- 最初の既定値（specular 0.7、shininess 18）では反射が地球の 1/5 を覆う白い円盤になりました。0.4 / 40 にしました。
- 大気のもやを b^10 にすると昼側の円盤全体が青白く曇りました。b^24 に絞りました。
- 参考値（`bin/mfs bench` ではなく開発中の1回の実行）: 初回フレーム 879〜1,076 ms、時刻を進める 120 フレームの
  frame 約 0.5 ms・GPU 約 0.08 ms、スライダーは 13 本とも次の rAF で描き直し（待ち時間込み 17〜19 ms）。
  初回フレームはテクスチャ 3 枚のデコードとミップマップ生成が大半とみていますが、まだ内訳を測っていません。
- 参考: threejs-006 の `globe.ts` は `UNPACK_FLIP_Y_WEBGL = 1` で v = 0 を北にしています。この版は反転なしで
  v = 0 が画像の1行目（北）になり、スクリーンショットでアジアが北、オーストラリアが南に出ることを確かめました。
