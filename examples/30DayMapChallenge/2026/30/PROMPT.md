# Day 30 implementation prompt — Pen & paper

Create an original map for **30DayMapChallenge 2026 · 30 Pen & paper** as a printable field-sheet for making a physical map by hand. Use real GSI elevation data around Mount Fuji. The generated print sheet should be the last digital step: light, source-based contour guides, a scale/north orientation and blank space for the user to add a route, annotations, and their own linework in pen on paper. Do not pass off the computer-generated sheet as a hand-drawn finished map, and do not generate images.

## Source and cartography

- Read `.agents/skills/yuiseki-open-data/SKILL.md` and catalog entry for `hf:gsi-dem-fuji-z14-100m-2026-10-25`; inspect its local README, `LICENSE`, source manifest and actual GeoParquet schema before use. The local dataset card says the file is `data/elevation_100m.parquet`, EPSG:3857, with 65,536 approximately 95.55 m Web Mercator cells, `elevation_mean_m/min_m/max_m` and `valid_pixels`; GSI source is DEM10B, and missing `e` values must not be treated as zero. Confirm current counts, exact extents, source tile hashes/date, coordinate transformation and terms.
- The source is under Japan's Public Data License 1.0 (PDL1.0) and GSI terms, not generic CC BY. Show the exact attribution and processing notice from the dataset card: “Source: Geospatial Information Authority of Japan (GSI), elevation tiles (Fundamental Geospatial Data elevation model), https://maps.gsi.go.jp/development/ichiran.html. Edited and aggregated into 10×10-pixel cells by yuiseki. This is not an official GSI product.” Link the GSI terms and explain the elevation source and its interpolation/accuracy limits.
- Choose a useful contiguous sheet extent within the DEM coverage and record its exact bounds, CRS conversion, grid and elevation ranges. Generate contour guides from `elevation_mean_m`; preserve `valid_pixels=0` as nodata gaps, not sea-level zero. Use a stated contour interval supported by the 100 m data (for example 100 m), show index contours more strongly, and avoid suggesting survey-level precision. The paper sheet must have a clear map title, contour interval/elevation units, scale bar with the correct ground distance, north indication, coordinates, a legend, a deliberate blank route/annotation area and printer margins.
- Contours are computed from source cell values. Show that the source grid represents aggregated and interpolated elevations, not an exact survey. Do not add fictional trails, labels, summit data, land boundaries or other unsupported features. Any summit marker must come from a cited source or be computed and labeled as a DEM maximum rather than asserted as an official summit position.

## Dedicated print renderer

- Implement a dedicated printable vector renderer from scratch. SVG generated from custom marching-squares contour extraction is appropriate; no generic map engine, map tiles, raster screenshots, generated imagery or external runtime service. A browser preview may show the same SVG and provide source-backed contour interval / extent controls, but the deliverable should be a deterministic print-ready A4 or A3 sheet that survives black-and-white printing.
- Keep generated contour paths as vectors. Include explicit physical page units, margins and a testable map scale. Make contour lines pale enough to invite hand annotation but dark enough to print reliably; index contours should be distinct. Provide an instruction to print at 100% scale, and clearly separate computer-generated guide lines from manual pen marks.
- Use only data that lies inside the selected source extent. Ensure pan/zoom or extent controls do not claim support beyond baked cells. If the output is `window.print()` rather than a standalone vector file, also provide a deterministic downloadable `.svg` built from the same tested renderer function.
