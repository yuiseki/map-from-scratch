# Day 29 implementation prompt — Raster

Create an original map for **30DayMapChallenge 2026 · 29 Raster** using real NOAA ETOPO 2022 15-arc-second bedrock elevation. Build a dedicated WebGL2 raster renderer that reads the COG's metadata and only the compressed tiles required by a fixed ocean-and-coast AOI through HTTP Range requests. The source is global real-world bathymetry/topography; do not replace it with a fictional surface or a generated image.

## Source verification and safe Range access

- Read `.agents/skills/yuiseki-open-data/SKILL.md` and the catalog entry for `z:planetarble/ETOPO_2022_15s_bed.tif`. Inspect the actual local file metadata, GDAL/COG layout, NOAA source card/terms and the exact citation/credit before writing `spec.yaml`. Do not read or copy the entire 3.3 GB file into a bake.
- Catalog facts to verify: NOAA ETOPO 2022 bedrock elevation; NOAA NCEI describes the dataset as not subject to U.S. copyright and waives related rights worldwide under CC0-1.0; global WGS84 raster, 86,400×43,200 Float32 at 15 arc-seconds; COG with 256×256 LZW tiles and eight overviews; nodata −99,999; unit metres; actual local path `/sata_hdd_24tb/www/html/static/planetarble/ETOPO_2022_15s_bed.tif`; public URL `https://z.yuiseki.net/static/planetarble/ETOPO_2022_15s_bed.tif`. Record the source URL, byte size, CRS, transform, nodata, block size, overviews, selected IFD/overview, tile offsets/sizes, and cite NOAA NCEI's ETOPO 2022 dataset (DOI 10.25921/fd45-gt74, accessed 2026-11-05) in docs and the benchmark output. Follow the official metadata's no-navigation limitation.
- The file is larger than Cloudflare's 512 MB cache limit. The open-data skill records that a first Range request can receive `200 OK` with the whole file, and later requests may receive `206 Partial Content`. Every request must inspect status and `Content-Range` before decoding. On an unexpected 200, abort/cancel the response body immediately; never call `arrayBuffer()` on it. Allow at most one bounded retry after cancellation; if the retry is not an exact 206 range, stop with a clear error and zero unbounded body consumption. Implement and test status-200 handling with a small synthetic response fixture. Do not warm the endpoint by downloading the COG.
- Make only small capped range probes (<60 s and `curl --max-filesize`) when needed. All data processes/tests/builds/browser runs must use `systemd-run --user --scope -q -p MemoryMax=8G -p MemorySwapMax=0 -p CPUQuota=400% -- <command>`.

## AOI and map design

- Choose one fixed rectangular AOI across Japan and the adjacent western Pacific where the source shows both land relief and the Japan Trench/nearby bathymetry. State its exact bounds and why it is useful. Use a COG overview appropriate to the screen resolution, fetch only intersecting tiles, and report compressed tile bytes and request count. The raster pixel grid—not any generated basemap—must drive the map.
- Implement only the TIFF/BigTIFF, COG, LZW and Float32 features actually present and required by this source. Validate endianness, IFD tags/chain, overview dimensions, tile offsets, byte counts, LZW decoded size, and geotransform. If a small focused decoder or TIFF parser is necessary, write it for the measured file profile and document its exact limits. Do not add a general-purpose map or raster engine; no external runtime packages, tiles, or APIs.
- Display ETOPO elevation in metres with a documented diverging/hypsometric palette, a visible zero sea-level reference, scale/coordinate context, and transparent treatment of nodata. Keep land elevation and negative bathymetry distinguishable, use a colour-blind-readable legend, and let a user inspect a pixel's longitude, latitude and source elevation. Pan/zoom only within supported coverage and reload the needed overview tiles as the view changes.
- Attribute NOAA and ETOPO 2022 as required by the source. Explain that ETOPO is a global relief model, not nautical-chart soundings, a navigation product, a coastal inundation model, or current terrain survey.
