# Day 29 implementation prompt — Raster

Create an original map for **30DayMapChallenge 2026 · 29 Raster** using NOAA ETOPO 2022 global 30 arc-second bedrock elevation. Build a dedicated WebGL2 raster renderer that reads the official tiled GeoTIFF metadata and requests only the compressed tiles needed for a fixed Japan-and-western-Pacific AOI through exact HTTP Range requests. The raster pixels—not generated imagery or basemaps—must drive the map.

## Source verification and safe Range access

- Use the official NOAA NCEI 30 arc-second global bedrock GeoTIFF: `https://www.ngdc.noaa.gov/mgg/global/relief/ETOPO2022/data/30s/30s_bed_elev_gtif/ETOPO_2022_v1_30s_N90W180_bed.tif`. The observed object length is 1,624,895,430 bytes. Verify the live response and actual metadata before writing `spec.yaml`; do not read or copy the whole file into a bake. The official `www.ngdc.noaa.gov` CORS response does not expose the `Content-Range` response header to JavaScript. Confirm exact byte offsets with capped `curl` probes; in the browser require HTTP 206, exact `Content-Length` and body length, known source object length, valid TIFF/decompression, and fixed decoded Tokyo/Fuji/Trench samples. If a browser can read `Content-Range`, validate it exactly. Never accept an unknown-length CORS response.
- Record the product URL, byte size, CRS, transform, dimensions, nodata, unit, tile/block dimensions, compression, predictor, overview availability, selected tile offsets/sizes, and cite NOAA NCEI's ETOPO 2022 dataset (DOI 10.25921/fd45-gt74, accessed 2026-11-06) in docs and benchmark output. The measured raster is 43,200×21,600 Float32, 30 arc-seconds, WGS84 + EGM2008, metres, nodata −99,999, 256×256 tiled, DEFLATE compression (TIFF compression tag 8), floating point Predictor=3, and no overviews. The NOAA server answered 206 for bounded Range reads and includes `Access-Control-Allow-Origin: *`. Respect the official metadata's no-navigation limitation.
- Source-selection investigation: the catalog's local 15 arc-second file at `/sata_hdd_24tb/www/html/static/planetarble/ETOPO_2022_15s_bed.tif` is 3,470,279,731 bytes and structurally a COG, but capped GDAL checks returned nodata at sampled coordinates across several continents and `STATISTICS_VALID_PERCENT=0` for a small Japan AOI. Its public URL served byte-identical metadata and sample tile bytes. The official 15 arc-second tiled directory did not list the Japan-area tile; a probe for `ETOPO_2022_v1_15s_N30E135_bed.tif` returned 404. Use the verified official 30 arc-second global file above as the source for this example and document this investigation in README.
- This file is larger than Cloudflare's 512 MB cache limit. The open-data skill records that a first Range request may receive `200 OK` with the whole file, and later requests may receive `206 Partial Content`. When `Content-Range` is browser-visible, inspect it and require an exact offset match. For this official CORS endpoint, the header is not exposed: require HTTP 206, the known object length, exact `Content-Length`, and the exact body length; then validate TIFF indices and decoded sentinel elevations. Verify actual offsets independently with capped `curl`. On an unexpected 200, abort/cancel the response body immediately; never call `arrayBuffer()` on it. Allow at most one bounded retry after cancellation and apply the same validation to its response. If the retry is invalid or its length is unknown, stop with a clear error and zero unbounded body consumption. Implement and test the CORS case, status-200 handling, and retry failure with small synthetic response fixtures. Do not warm the endpoint by downloading the source.
- Make only small capped Range probes (<60 s and `curl --max-filesize`) when needed. All data processes/tests/builds/browser runs must use `systemd-run --user --scope -q -p MemoryMax=8G -p MemorySwapMax=0 -p CPUQuota=400% -- <command>`.

## AOI and map design

- Use the measured fixed AOI `[138.5°E, 34.5°N, 144.5°E, 40.5°N]` from central Honshu to the western Pacific Japan Trench; it contains Tokyo, Mt. Fuji and trench Float32 samples with enough surrounding terrain for context. At 30 arc-seconds this selects 16 of 14,365 tiles (2,123,065 compressed bytes) in four contiguous Range spans. The official TIFF directory and tag arrays end below byte 131,072, so read a 131,072-byte metadata prefix, then the four tile spans in parallel: 2,254,137 source bytes across five HTTP 206 requests. Verify these figures in the implementation and browser. The raster has no overviews, so fetch only the intersecting 256×256 tiles from its TIFF index. Do not fetch unrelated tiles or the whole file.
- Implement only the classic TIFF, DEFLATE, Predictor=3 and Float32 features present in this source. Validate endianness, IFD tags, tile offsets, byte counts, DEFLATE output bounds, Predictor=3 byte-plane reconstruction, Float32/nodata semantics and geotransform. If a focused parser/decoder is needed, document its exact limits. Use the browser's native bounded `DecompressionStream('deflate')`; do not add runtime packages, other tiles or APIs.
- Display ETOPO elevation in metres with a documented diverging/hypsometric palette, a visible zero sea-level reference, scale/coordinate context and transparent nodata. Keep land elevation and negative bathymetry distinguishable, use a colour-blind-readable legend, and let a user inspect a pixel's longitude, latitude and source elevation. Load the selected fixed AOI's blocks once, retain its Float32 pixels in memory and pan/zoom within this loaded coverage; do not imply additional source tiles are loaded during navigation.
- Attribute NOAA and ETOPO 2022 as required by the source. Explain that ETOPO is a global relief model, not nautical-chart soundings, a navigation product, a coastal inundation model, or a current terrain survey.
