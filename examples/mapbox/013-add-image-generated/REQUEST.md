# Mapbox: Add an image (generated)

Mapbox GL JS の公式サンプル「[Add an image (generated)](https://docs.mapbox.com/mapbox-gl-js/example/add-image-generated/)」を写経し、外部ライブラリ（MapLibre / Mapbox 等）を使わずに最小・最速の専用描画器を作成してください。

## 依頼内容
1. 中心 `[0, 0]`、`zoom: 2` の世界地図を表示する。
2. 64×64 のグラデーション画像をコードでピクセルごとに生成する（赤が x、緑と青が y に比例）。
3. その画像をアイコンとして `[0, 0]` に置く。
4. アイコンはズームしても 64 px の画面サイズを保つ（symbol アイコンの挙動）。

## 元例との差分

- 元例は `map.addImage` で生成画像を登録し、symbol レイヤーの `icon-image` で表示する。ここでは起動時にオフスクリーン Canvas に生成し、`drawImage` で画面サイズのアイコンとして描く。
- 背景は Mapbox のベクター地図ではなく Natural Earth 陸地塗り（ズーム 2 の世界スケール）。

## 設計の意図と判断

1. **生成は起動時に 1 回だけ**
   - 16 KB のピクセル書き込みを毎フレームやると 60 fps の予算を無駄に食う。オフスクリーン Canvas に置けば、以降は `drawImage` 1 回で済む。
2. **画面サイズのアイコンとして描く**
   - Mapbox の symbol アイコンはズームしても大きさが変わらない。地理座標の矩形として描く image ソースと混同すると、拡大時にアイコンが地図と一緒に膨らむ。
3. **グラデーションで向きを証明する**
   - 赤が x、緑と青が y に比例する画像は、4 隅の画素を読むだけで転置・反転を検出できる。単色アイコンでは位置の誤りに気づけない。
4. **期待値は検証側でも独立に計算する**
   - 生成式をベンチにも書き、レンダラの画素と ±1 以内で一致することを確かめる。描画器の関数から期待値を取ると、式のバグを見逃す。

## 計測結果

| 項目 | 値 |

| 初回描画 first_frame_ms p50 | 18.41 ms |
| 再描画 redraw_ms p95 | 0.53 ms |
| フレーム間隔 frame_interval_ms p95 | 0.875 ms |
| コード gzip | 2,908 B |
| データ gzip | 30,400 B |
| 検証チェック | 5 / 5 PASS |

## 検証チェック

- `map-rendered-at-target`: サハラが陸地、大西洋が海。
- `gradient-icon-generated`: 64×64 のアイコンが投影した `[0,0]` を中心に置かれる。
- `gradient-orientation`: 4 隅の画素が独立計算した生成式と ±1 以内で一致。
- `icon-follows-pan`: 120×60 px パンでアイコンと地物が同じだけ動き、画素は不変。
- `icon-keeps-screen-size-on-zoom`: zoom 2 → 5 でアイコンは 64 px のまま、周囲の地物は 8 倍に広がる。

## データ

- アイコン画像は配信せず、起動時にコードで生成。
- Natural Earth 110m 陸地（パブリックドメイン）を Web Mercator へ投影。

## 実装上の落とし穴

- `Uint8ClampedArray` は 0.5 を偶数丸めする。x=32 のような半端値でのみ差が出るため、検証点は 4 分の 1 の位置に置いて丸めの差を避けている。
- `drawImage` を非整数座標に置くとバイリニア補間で画素が混ざる。厳密比較するときは初期ビューのような整数座標で読む。
