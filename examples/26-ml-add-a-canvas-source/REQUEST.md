# 26 アニメーションする canvas を地図に重ねる (MapLibre の例「Add a canvas source」)

## 依頼

> MapLibre の例「Add a canvas source」と同じものを作りたい。自分のページで描いているアニメーションの canvas (400x400、円が5つ跳ね回る) を、ミャンマーの上の4隅の座標に合わせて地図に貼り、地図は動かせるようにする。地図は MapLibre のデモの地図 (demotiles) と同じ見た目でよい。

原本: `ref-repos/maplibre__maplibre-gl-js/test/examples/add-a-canvas-source.html`。中心 (95.899147, 18.088694)、ズーム 5、最小ズーム 4、4隅は (91.4461, 21.5006) から (100.3541, 13.9706)。

## 読み取った要件

| 要件 | 数値にしたもの (spec.yaml の evaluation.budgets) |
| --- | --- |
| canvas が4隅にぴったり重なり、地図を動かしても付いてくる | 機能確認 overlay-on-corners: 4 視点 (原本、z4、z7.3、経度を 360° ずらした視点) で、canvas の画面上の外接矩形と4隅の投影位置の差が 0.5 px 未満 |
| アニメーションが地図の描画を巻き込まない | カメラを止めた 240 フレームのあいだ地図の描き直し 0 回 |
| なめらか | 60 Hz の歩調のパンでフレーム間隔 p99 20 ms 以下。vsync なしのパンとズームで平均 16.7 ms 以下。アニメーション中の間隔 p95 20 ms 以下。1 回の描き直しの記録 p95 12 ms 以下 |
| すぐ出る | 初回描画 p50 600 ms 以下 |
| 小さい | コード gzip 5,000 B 以下、データ gzip 320,000 B 以下 |
| demotiles と同じ見た目 | 機能確認 basemap-colours (海、ミャンマー、タイの色を画面の canvas から読み戻す) と目視 |

画面は PC (1280x800、DPR 1)。原本が PC 向けの全画面の地図なので。

## やらないこと

回転、傾き、地球儀、ベクトルタイル、スタイルの解釈、都市や道路。4隅が台形になる貼り方 (Web Mercator で経緯度の矩形は長方形になるので、この依頼では要らない)。

## 設計

- 重ねる canvas は地図にコピーしない。canvas 要素をそのまま地図の上に置き、4隅のうち3点の投影位置から作った CSS の `matrix()` で貼る。ページが canvas に描くたびに、それはブラウザの合成器が画面に出す。地図がするのは、カメラが動いたときに変換を1つ書き換えることだけ。MapLibre の canvas ソースは `animate: true` のとき、毎フレーム canvas をテクスチャに送り直して地図全体を描き直す (`src/source/canvas_source.ts`)。
- 地図は Canvas 2D の1枚で、カメラが動いたときだけ描く (animation-and-camera スキルの on-demand redraw)。
- 国は Natural Earth 10m (demotiles の元データと同じ) から作る。Web Mercator の単位正方形を 65,536 単位のグリッドにし、グリッド上で Douglas–Peucker 4 単位 (ズーム 5 で 1 px) に単純化、1 px² 未満の輪を落とす。1 国 1 本の SVG パス文字列 (輪の最初の点だけ絶対座標、あとは相対の整数) にして、描画器は `Path2D` にそのまま渡す。Path2D は国が初めて画面に入ったときに作る。
- 外接矩形で画面外の国を飛ばす。経度方向は世界のコピーの数だけ描く。
- 配色と線幅とズームごとの変化は demotiles の style.json の値を写した (countries-fill の ADM0_A3 による塗り分け、coastline、countries-boundary、geolines、国名)。海岸線は太い青の線を先に描き、その内側半分を国の塗りが覆う。原本のスタイルと同じ順番。
- 国名は LABELRANK と面積の順にベイクし、描画器はその順に貪欲に置いて、重なるものを飛ばす。10 em で折り返す (text-max-width)。
- 回帰線や北極圏の線は Mercator ではまっすぐな水平線なので、データを持たず緯度から描く。
- 重ねる canvas のアニメーションは原本と同じ (半径 20 の円が5つ、壁で跳ね返る)。計測で毎回同じ円になるよう、乱数だけ種つきにした。

## 計測で分かったこと

- 240 フレームのアニメーション中、地図の描き直しは 0 回。アニメーション中のフレーム間隔は p50 0.28 ms、p95 0.7 ms (vsync なし)。canvas の中身はフレームごとに変わっている (overlay-animates)。
- 初回描画 p50 58 ms (最後の 5 回。その前の 5 回は 94 ms)。コード gzip 3,952 B (canvasmap.ts と main.ts)、データ gzip 299,700 B (basemap.json、生 736,900 B、247 か国、13 万頂点)。データは世界全体の1ファイルで、この画面で見えるのはその一部。z4〜z8 の東南アジアだけなら小さくできるが、描き直しの記録が p95 1.1 ms (5 回で 2,400 回) に収まっているので分けなかった。
- vsync なしのパンとズームは平均 4.4 ms と 5.5 ms、p50 1.4 ms と 3.3 ms。ただし約 33 フレームごとに 35〜70 ms (最初の回は 400 ms) 止まる。描き直しの記録 (redraw_ms) は最大でも 6 ms なので、止まっているのは記録ではない。ハーネスは vsync を切るので、メインスレッドが GPU プロセスより先に走って、ときどき待たされていると考えた。
- この仮説を確かめるため、同じパンを 60 Hz の歩調 (16.7 ms に1歩) で動かした。720 フレーム中 717 が 16.3〜16.9 ms で、20 ms を超えたのは 3 つ (52、35、21 ms)。止まりの大半は vsync なしの計測が作ったもので、利用者の画面では 240 フレームに1回ほどのつかえになる。なめらかさの予算は 60 Hz の歩調の p99 にし、vsync なしの値は平均で余裕を見ることにした。
- 重ねた canvas の位置は 4 視点で外接矩形と投影位置の差が 0.5 px 未満。経度を 360° ずらした視点でも、近いほうの世界のコピーに付く。
- MapLibre の原本とは同じ条件で並べて測っていない。MapLibre GL JS 本体だけで gzip 約 286 KB (README の 02 の比較)。
