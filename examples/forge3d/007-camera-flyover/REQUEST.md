# forge3d-007-camera-flyover

レーニア山の地形の上をカメラが飛ぶアニメーション。山頂を回るオービット、登山道を登る人を後ろから追うフォロー、北側を横切るレールの 3 つのカメラワークを切り替えられ、再生と一時停止、時刻のスライダーで好きな瞬間に飛べる。カメラは地面に潜らない。0°、120°、240° のコマも並べる。外部ライブラリなし。

## 元の例

- forge3d: [Camera Flyover](https://milos-agathon.github.io/forge3d/gallery/07-camera-flyover.html)
- 元の例には 2 つの書き方がある。
  - 低レベル: レーニア山のビューアで `set_orbit_camera(phi, theta=50, radius=5400)` の phi を 20° ずつ回し、1 コマずつ撮る。画像は 0°、120°、240° のコマ 3 枚。
  - リグ: `TerrainOrbitRig` (phi 20°→320°、6 秒) を `TerrainClearance(minimum_height)` 付きで秒 60 標本の `CameraAnimation` に焼く。用意されたショットはオービット、レール、フォローの 3 つ。

## 設計

1. 地形は forge3d-001 のベイク (rainier.bin) と描画 (1 ドローコール) をそのまま使う。この例のベイクはない。
2. カメラワークは「時刻 t の目と注視点」を返す関数で、ページを開いたときに秒 60 標本へ焼く (3 本、計 1,445 標本、約 11 ms)。
   - オービット: 山頂を中心に phi 20°→320°、仰角 40° (forge3d の theta 50°)、6 秒。forge3d の radius は forge3d のシーンの単位なので、元の画像と同じ見え方になる 14 km にした。
   - フォロー: パラダイス (1,650 m) からミューア雪原を通ってキャンプ・ミューア、山頂へ向かう人を、1.4 km 後ろ、350 m 上から追う。10 秒。登る人は常に地面の上に置く。
   - レール: 山頂の 7 km 北、標高 2,000 m の直線を西から東へ、山頂を見たまま横切る。8 秒。途中の尾根は線路より高い。
3. 地面からの余裕 (forge3d の TerrainClearance) は焼くときに守る。
   - 標本ごとに「地面 + 余裕」まで持ち上げるだけだと、尾根ごとにカメラが跳ねる。
   - 持ち上げた高さに幅 ±0.25 秒の移動最大を取り、同じ幅で移動平均する。各標本はそれを含むどの窓の最大よりも低くないので、平均しても持ち上げた高さを下回らない。
4. 再生はフレームの数ではなく時計で標本を引く。遅いフレームがあれば標本を飛ばし、飛行の速さは変わらない。
5. コマ 3 枚は、読み込み時に WebGL のキャンバスへ forge3d の低レベルの視点 (phi 0°、120°、240°) で描き、Canvas 2D に縮小して写す。

## 計測結果

`bin/mfs bench forge3d-007-camera-flyover -n 3` (1024x768、DPR 1、ANGLE / NVIDIA RTX 3060)。

| 項目 | 値 | 予算 |
| --- | --- | --- |
| 初回描画 first_frame_ms p50 (焼き込みとコマ 3 枚を含む) | 70.5 ms | 500 ms |
| カメラワークの焼き込み rig_bake_ms p50 | 11.8 ms | 50 ms |
| 再描画 redraw_ms p95 | 0.025 ms | 8 ms |
| フレーム間隔 frame_interval_ms p95 (1 秒の再生) | 0.52 ms | 20 ms |
| コード gzip | 7,683 B | 9,000 B |
| データ gzip (forge3d-001 と同じ rainier.bin) | 540,000 B | 650,000 B |

redraw_ms は CPU が描画命令を出し終えるまで、frame_interval_ms は vsync なしの rAF の間隔で、どちらも GPU の実行時間は含まない。

## 検証チェック

- `clearance-holds`: 3 本の全標本で、カメラが地面から余裕以上の高さにあり、レールでは実際に持ち上げた標本がある。
- `orbit-baked-at-60hz`: どれも標本数が「長さ x 60 + 1」で、オービットの最初と最後の方位が 20° と 320°。
- `follow-keeps-the-target`: フォローの 11 時点で、登る人が画面の中央 (1 px 未満) にあり、地面の上にいて、そこに地形が描かれている。
- `scrub-is-repeatable`: レールの 200 標本目に戻ると 3 点の画素が一致し、400 標本目とは違う。
- `film-strip-drawn`: コマ 3 枚がどれも 30% 以上地形で、3 枚とも違う。
- `playback-follows-the-clock`: オービットを 1 秒再生すると、進んだ標本数が経過時間 x 60 と 4 標本以内で一致し、絵が動いている。

## 開発中に見つけたこと

- `follow-keeps-the-target` が最初は 11 時点中 2 時点しか通らなかった。登る人の高さを 3 つの経由点の間で直線に補間していたため、経由点の間では斜面から浮いたり潜ったりしていた。各時点で地面の高さに置くよう直した。
- 最初はオービットの半径を forge3d の 5400 をそのまま 5.4 km にしていた。山頂が画面を埋めて元の画像と見え方が違ったので、forge3d の radius は forge3d のシーンの単位だと考え、14 km にした。そこから見ると forge3d-001 の霞 (26 km で薄れる) では山が白っぽくなりすぎるので、この例では 60 km にした。

## 元の例との違い

- 元の例はコマを画像として書き出す。ここではブラウザで再生し、スライダーで動かせる。動画への書き出しはしない。
- 元の例のレールはルクセンブルクの地形の上。ここにはレーニア山の地形しかないので、レーニア山の北側に置いた。
- 視線が地形を貫くこと (カメラと注視点の間の尾根) は避けていない。元の例のリグも余裕はカメラの高さだけに掛ける。
